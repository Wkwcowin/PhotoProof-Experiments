# PhotoProof 代码复现进展

2026 年 10 月 13 日 王科文

这次运行了 GitHub 上的 [PhotoProof Go 实现](https://github.com/drakstik/PhotoProof)。PhotoProof 要解决的问题是：照片经过允许的编辑后，如何证明它仍然来自原始照片。

**目前已完成图像签名、证明生成和证明验证的基本流程。** 原代码未修改，在 Apple M1 电脑上连续运行了 3 次，签名和证明验证均通过。

实验使用程序生成的 6×6 数字矩阵模拟图像，还没有使用真实照片。程序先对模拟图像签名，再生成 Groth16 零知识证明，最后检查证明是否通过。

| 运行 | 证明计算耗时 | 证明验证耗时 | 验证结果 |
| --- | ---: | ---: | --- |
| 第 1 次 | 44.20 ms | 1.05 ms | 通过 |
| 第 2 次 | 44.66 ms | 1.13 ms | 通过 |
| 第 3 次 | 45.20 ms | 1.03 ms | 通过 |

时间取自程序日志。证明计算时间不含约束求解、编译和密钥生成，因此不是程序总耗时。这里只做了 3 次小规模实验，暂时不能代表处理真实照片时的性能。

**当前代码只支持图像保持不变的情况，尚未实现裁剪、旋转等编辑操作。** 另外，检查代码时发现，验证证明的步骤没有重新核对传入图像与证明是否对应。因此，目前确认的是演示程序可以运行，还不能说明它已经能够可靠地认证编辑后的照片。

随后使用真实图片 `1.JPG` 做了对照实验：保留原图的签名和证明，分别测试原图、裁剪图和添加红色方块的图。原图的两项检查均通过；编辑后的两张图被签名检查拒绝，却仍被证明检查接受，确认了上述问题。详见[真实图片实验](real-photo/真实图片实验.md)。

在新增的裁剪版本中，已补上图片与证明的对应检查，并加入指定范围的裁剪规则。使用同一张真实图片测试，合法裁剪能够通过，修改像素、添加方块或裁错区域均被拒绝。详见[裁剪实验结果](crop-auth/裁剪实验结果.md)。

后续版本进一步支持签名后选择不同的裁剪位置和尺寸、直角旋转，以及在结果图上继续编辑。三个真实图片实验通过，改像素和篡改操作参数均被拒绝；裁剪仍需按分块边界对齐。详见[本次进展](flex-auth/本次进展.md)。
