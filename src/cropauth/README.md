# 允许指定裁剪的实验版本

这个版本补齐了原 Demo 缺少的图片对应检查，并增加了裁剪规则。原来的 `main.go` 保留不变，新入口是 `cmd/cropdemo`。

## 实现方法

1. 签名方读取原图的 RGB 像素，按固定大小分块，对每块计算 SHA-256。每个 256 位摘要分成两个 128 位数，避免直接取模丢失摘要信息。
2. 将图像尺寸、分块大小、允许的裁剪坐标和尺寸、所有原图块摘要按固定顺序输入 MiMC，得到原图及规则的承诺值。签名方对这个值进行 EdDSA 签名。
3. 证明电路重新计算上述承诺值并验证签名，再检查输出块摘要是否逐一等于允许裁剪区域内的原图块摘要。
4. 验证者读取实际收到的图片，重新计算输出块摘要，将它们作为 Groth16 的公开输入进行验证。修改任意像素都会改变公开输入，原证明无法继续通过。

SHA-256 在电路外计算：签名方负责从原图像素生成原图块摘要，验证者负责从收到的图片生成输出块摘要。电路认证的是已签名摘要之间的裁剪关系，不在电路内执行 JPEG 解码或 SHA-256。这依赖签名方正确读取和签名原图，以及 SHA-256、MiMC、EdDSA 和 Groth16 的相关安全假设。

公开输入包括规则、原图承诺、签名、公钥和裁剪后图片的块摘要。秘密输入是原图的完整块摘要列表。验证者不需要获取原图，也不接收编辑者自报的公开见证文件。

## 已验证的实例

输入为 `1.JPG`，1440×810 像素，没有缩小。分块大小为 90×90，原图共 16×9 块；允许的操作为从坐标 `(360, 0)` 保留 720×810 像素，也就是中间 8×9 块。

合法裁剪通过；改变一个像素、添加红色方块、换成同尺寸的其他区域、用原图代替裁剪图均被拒绝。尝试为改变像素后的图片重新生成证明，约束系统也拒绝。另有小图测试覆盖不同签名方、不同原图、不同规则及无效签名等情况。

## 运行

以下命令从 `src` 目录执行。结果目录必须是新的，以免覆盖已有记录。

```bash
go run ./cmd/cropdemo -input ../1.JPG -out ../experiment-results/crop-auth-new
```

生成结果包括：裁剪图、篡改对照图、签名证书、证明文件、规则与签名公钥、验证密钥及 JSON 实测数据。实验中的签名密钥临时生成，不保存私钥。

单独验证已有结果：

```bash
go run ./cmd/cropdemo -mode verify \
  -trusted ../experiment-results/crop-auth/trusted \
  -certificate ../experiment-results/crop-auth/certificate.json \
  -proof ../experiment-results/crop-auth/proof.bin \
  -image ../experiment-results/crop-auth/crop.png
```

把最后一行改为 `one-pixel-changed.png`，程序应输出 `REJECT` 并以非零状态退出。

`-trusted` 指向验证者预先信任的规则、公钥和验证密钥，不能改为编辑者任意提供的信任根。演示程序在同一台机器上模拟签名方、证明方和验证方；独立验证只需要可信配置、证书、证明和裁剪图，不需要原图或证明密钥。

运行测试：

```bash
go test ./cropauth -count=1 -v
```

## 适用范围

- 每份签名只允许一个事先指定的裁剪矩形，坐标和尺寸必须对齐分块边界。本次不支持编辑者事后任意选择裁剪范围；改变规则需要重新生成参数并签名。
- 校验对象是解码后的不透明 RGB8 像素，不包括 EXIF、文件压缩字节或拍摄内容真实性。裁剪结果使用 PNG 保存，不支持 JPEG 再压缩造成的像素变化。
- 原图按分块边界划分，不支持边缘不足一块的尺寸。当前命令默认参数适配提供的 1440×810 图片。
- 这是一个可运行的有限裁剪方案，不包含旋转、缩放、多轮递归证明，也不是论文完整 PCD 构造。Groth16 参数仍通过本地可信 Setup 生成，未进行生产级密钥管理或独立安全审计。
